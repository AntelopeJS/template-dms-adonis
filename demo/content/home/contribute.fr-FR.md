## Contribuer correctement

Le DMS et ses modules sont open source. Pour qu'une contribution soit acceptée vite :

- **Discutez d'abord** une fonctionnalité importante dans une issue.
- **Une branche, un sujet** — un correctif ou une fonctionnalité par pull request, petite et relisible.
- **Générique dans les modules, spécifique dans le projet** — un module ne contient jamais le contenu d'un client ; une option générique avec une valeur par défaut sûre, oui.
- **Lancez les vérifications du dépôt** (formatage, lint, types, tests) et ajoutez tests et documentation quand le comportement change.
- **Commits conventionnels** (`fix(api): …`, `feat(tables): …`) et une description qui explique le problème, la solution et la preuve de test.
- **Les mainteneurs fusionnent et publient** ; le projet met ensuite à jour la version du module.
